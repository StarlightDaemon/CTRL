# CTRL repository closure report

> **Dependency follow-up, 2026-10-16:** the two dependency findings recorded
> below have been patched. See the [remediation report](2026-10-16-dependencies.md)
> for verification and additional advisory findings. This report retains the
> original closure snapshot.

CTRL is deprecated at the operator's request. Development, maintenance and
release plans have ended. The repository is retained for historical reference,
with GitHub archiving used to enforce read-only status after this report is
published. Existing installations receive no further security updates.

No confirmed live CTRL credential was found. One critical development dependency
alert remains open, and the previously reported Chromium key remains in retained
pull-request history. Repository closure does not remediate either finding.

## Final changes

- Added the deprecation header at the top of the README without an explanation
  of the project's former operational role.
- Marked contribution guidelines, roadmap and release plans as historical.
- Removed supported-version and security-response commitments.
- Recorded D-007 and retired unfinished development work without claiming it was
  implemented. Preserved unresolved security follow-ups and historical records.
- Preserved existing local RAIDEN state and Serena edits. Prepared the published
  changes from clean `origin/main` at `f9e4057`, rather than including local edits.
- Repository Actions are disabled before publication; GitHub archiving is the
  final remote operation. The operator closeout confirms the resulting settings.

## Credential review

Review date: 2026-10-15, America/Denver. Baseline: remote `main` at `f9e4057`;
original checkout at `3fa44f1`, with existing local edits retained.

Gitleaks 8.30.1 scanned the working directory, including ignored local reports
and source ZIP artifacts, with archive traversal depth 2, redaction enabled and
inline allow comments ignored. It reported 8 matches across approximately
14.65 MB. History scanning with `--all --full-history` covered 266 commits after
fetching every advertised pull-request head and reported 15 matches across
approximately 13.30 MB of diff content.

A separate byte-pattern sweep inspected all 3,677 local Git objects, including
all 2,143 blobs (38,856,828 bytes), to cover binary cache data and objects outside
ordinary text diffs. It checked Google, GitHub, AWS, OpenAI/Anthropic and Slack
key formats, private-key headers, complete JWTs and URLs containing credentials.
Values were represented only by fingerprints in the local scan output.

| Finding | Assessment and disposition |
| --- | --- |
| Chromium Google API key in 16 historical browser-cache blobs | Confirmed residual exposure through public `refs/pull/3/head`, commit `15ffee9`. All 16 occurrences have the same fingerprint and omnibox suggestion context. [GitHub secret alert 1](https://github.com/StarlightDaemon/CTRL/security/secret-scanning/1) is resolved with reason `revoked`. Provider-side revocation remains independently unverified; OL-011 remains unresolved. If the owner needs the historical data removed, pursue a GitHub Support purge. Archiving and deleting a local backup tag do not remove the PR ref. |
| BiglyBT unit-test API key, including the local source ZIP | Explicit fixture `test-api-key-12345`; no live endpoint or operational credential established. |
| Archived Synology research and a local audit quotation | Illustrative session-token text and truncated JWT header examples; no complete signed JWT or CTRL credential established. |
| Three historical Chromium Preferences matches | Two built-in extension manifest public keys and one `protection.macs.enterprise_signin.policy_recovery_token` integrity MAC. These are not private keys or a confirmed reusable service login token. |
| Three URLs with embedded user information in Git blobs | Two unit-test inputs using example hosts and one documentation example using placeholder credentials. |

The byte sweep found no GitHub tokens, AWS access-key IDs, OpenAI/Anthropic
keys, Slack tokens, complete JWTs or private-key headers in local Git blobs.
A filename review found no project environment files, private-key files or
credential-store files outside vendor directories. Identifier-level review
found application code that accepts user credentials, rather than hard-coded
operational credentials. No secret values are included in this report.

Coverage is bounded by Gitleaks' default rules and vendor allowlists, archive
depth 2 and the supplementary byte patterns. This is a credential-exposure review,
not a full code audit or proof that no unknown secret exists. Encrypted payloads,
image contents, external service credentials, GitHub Actions secret values and
provider-side credential validity are outside the inspection. No credential was
used to test authentication to its provider.

## Outstanding dependency findings

GitHub reported these two open Dependabot alerts on the default branch at review
time. Both are transitive development dependencies in `extension/package-lock.json`.

| Severity | Finding | Impact and disposition |
| --- | --- | --- |
| **Critical** | [`shell-quote` 1.9.0, alert 95](https://github.com/StarlightDaemon/CTRL/security/dependabot/95), [GHSA-pqg4-j6r4-53mv](https://github.com/advisories/GHSA-pqg4-j6r4-53mv) | Command injection when an attacker-controlled string with a line terminator follows a comment token in the same `quote()` call and the result reaches a shell. Fixed in 1.11.0. Development/build exposure is confirmed by the alert; exploitability in CTRL was not established. Unfixed at closure. Before reviving the toolchain, update the dependency and validate it. |
| Medium | [`brace-expansion`, alert 93](https://github.com/StarlightDaemon/CTRL/security/dependabot/93), [GHSA-q2hr-2g5m-vwhr](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr) | CPU denial of service from quadratic expansion. The affected 2.x range is below 2.1.7. Unfixed at closure; update the affected transitive instance before reviving development. |

No dependency change is included in this closure. Development-scoped alerts do
not by themselves establish exposure in the shipped extension. The archive
retains these findings without promising future remediation.
